## Findings, in priority order

### P1 — Locked dependencies have reported vulnerabilities

The live PyPI-backed `pip-audit` reported:

| Package | Locked/installed | Advisories | Reported fixed version |
|---|---|---:|---|
| certifi | 2026.7.22 | 1 (`PYSEC-2026-4320`) | 2026.10.19 |
| Pillow | 12.3.0 | 35 | 13.0.0 |

Both versions are present in [`uv.lock`](../../uv.lock). Installed Streamlit **1.65.0**
declares `pillow<13,>=7.1.0`, so forcing the reported Pillow fix into the environment
would violate its dependency constraint. No dependency or environment mutation was
made during this audit. Advisory counts describe the scanner result; exploitation
of an application path was not assessed.

Follow-up: update certifi in the lockfile and find a supported Streamlit/Pillow
combination that addresses the scanner findings, then sync the locked environment and
rerun all verification. Preserve the dependency versions recorded with existing study
artifacts; do not regenerate old research evidence merely to use newer packages.

### P1 — Frozen selection and final-test evidence can be overwritten

[`lock_frozen_study`](../../src/bikepulse/ml/frozen_study.py#L844) overwrites
`selection.json` regardless of whether the test has completed. Likewise,
[`run_frozen_test`](../../src/bikepulse/ml/frozen_study.py#L1007) rewrites final metrics
and predictions, and preparation/full validation can reset state or overwrite models.
The lifecycle records state but does not enforce forward-only transitions.

Reproduced entirely under a temporary directory using the synthetic export fixture in
`tests/test_ml_frozen_study.py`: prepare, fit, lock `logistic_core`, evaluate, re-lock
`hist_core`, evaluate again. Both later calls succeeded, and `test_metrics.json`
changed. The real frozen study was never scored or modified.

This allows post-test selection and loss of the original evidence. Follow-up: enforce
immutable selection/test artifacts and permitted lifecycle transitions, reject
retraining/reselection after locking, and cover repeated and out-of-order commands
with synthetic regression tests. Existing reports do not establish that the recorded
real execution abused this path.

### P2 — One non-object station entry aborts an otherwise valid response

Both normalizers in [`collector/schemas.py`](../../src/bikepulse/collector/schemas.py#L110)
call `raw.get(...)` before per-record validation. `GbfsPayload` checks that `stations`
is a list, but does not require each member to be an object.

Reproduced by loading each valid fixture, appending JSON `null` to `data.stations`,
and normalizing it. Both raise `AttributeError` instead of returning valid records
and one `RecordError`. In the map this can trigger last-known/unavailable fallback;
in compaction it can prevent an hour containing that snapshot from rebuilding.

Follow-up: validate member shape before field access and retain record-level errors
for malformed members. Test mixed valid and malformed entries for both feed types.

### P2 — Temporal feature-cache provenance omits upstream transformations

The [`temporal cache key`](../../src/bikepulse/ml/temporal_study.py#L165) includes the
status-source fingerprint, development boundary, radius, schema version, and
`temporal_features.py`. It does not include `dataset.py`, which supplies
`canonical_grid`, or compaction logic/station metadata used by `load_history`.
The temporal run ID also omits these inputs and dependency versions.

Static code inspection shows that changing observation-selection semantics or derived
history can leave the same cache key and cause cached features to be reused. No
history or source code was mutated to demonstrate this on the real dataset.

Follow-up: include the complete transformation/input provenance in cache and run
identities, validate cached artifact checksums/schema, and test invalidation when an
upstream transformation changes.
